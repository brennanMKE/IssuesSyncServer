# 0012 — Cross-platform passkey: a web-registered iCloud Keychain passkey must sign in the native Mac app

| | |
|---|---|
| **Status** | open |
| **Module** | auth / api / infra |
| **Platform** | All |
| **First seen** | 2026-06-25 |

## Description

Intended flow (from the project owner): register an account in the **browser**
on `https://sync.sstools.co` — the WebAuthn ceremony creates a passkey that
lands in **iCloud Keychain** scoped to RP ID `sync.sstools.co`. Then sign in
from the **native Mac app** using that *same* synced passkey, with no separate
device enrollment.

`RemoteSync.md:88` already assumes "the same RP works for the web admin and for
the native app," but the supporting plumbing that Apple requires for a native
app to use a web-created passkey is not present in the repo. Three concrete
backend gaps block this flow today:

### 1. Serve `/.well-known/apple-app-site-association` (AASA) — missing entirely

Apple only lets a native app use a passkey for `sync.sstools.co` if that origin
serves an AASA file containing a `webcredentials` entry for the app's
`<TeamID>.<BundleID>`. There is no such handler or file anywhere in the repo.

- Serve at `GET /.well-known/apple-app-site-association`, `Content-Type:
  application/json`, **no redirect**, over HTTPS, on the same host as `RP_ID`.
- Body shape:
  ```json
  { "webcredentials": { "apps": ["<TeamID>.<BundleID>"] } }
  ```
- The Mac app's identifiers live in `../Issues`; make team ID + bundle ID
  configurable (env, e.g. `WEBCREDENTIALS_APP_IDS`) rather than hard-coded.

### 2. Discoverable (usernameless) assertion — not supported

The current service only does email-scoped login: `BeginAssertion` →
`loadUserByEmail`, and `FinishAssertion` derives the user from `sess.UserID`
(`internal/auth/webauthn.go`). Signing in on the Mac by simply picking the
synced passkey requires resolving the user from the assertion's credential ID.
Add `BeginDiscoverableLogin` / `FinishDiscoverableLogin` (look the credential up
by raw `credential_id`, as the sibling ShortLinks server does in `FinishLogin`
via `CredentialByID` — see `../ShortLinks/docs/passkeys.md` and audit #0011).

### 3. Registration must mint a discoverable, syncable credential

`BeginRegistration` uses library defaults. For the passkey to sync to iCloud
Keychain and be discoverable on the Mac, the registration policy must set
`residentKey: required` + `userVerification: required` (again per the ShortLinks
`registrationOptions()` policy in #0011).

Also note: the native `/v1/auth/*` endpoints are still `stubNotImplemented`
(501) in `internal/api/router.go` and must be wired to the auth Service for the
Mac assertion path to exist at all. (#0007 lists these endpoints but assumes
they already work; they don't yet.)

### 4. Account creation from the Mac (registration is not web-only)

The same passkey symmetry means an account can equally be *created* from the
native app: the Mac runs a registration ceremony via
`ASAuthorizationPlatformPublicKeyCredentialProvider`'s
`createCredentialRegistrationRequest`, and the resulting passkey syncs to iCloud
Keychain so it then works in the browser too. To support this, the native
`/v1/auth/begin-registration` + `/v1/auth/finish-registration` endpoints must
accept the **invite / enroll token** (onboarding is invite-based per
`RemoteSync.md:81-82` — first admin via the bootstrap enroll URL, others via a
mailed invite), so the new credential binds to the correct email/user. There is
no anonymous public sign-up; "create an account from the Mac" means redeeming an
invite/enroll token natively instead of in the browser.

## Mac-side dependency (in `../Issues`, tracked under #0007)

For the same passkey to be reachable from the app, the Mac side must also:

- Add the **Associated Domains** entitlement `webcredentials:sync.sstools.co`.
- Use `ASAuthorizationPlatformPublicKeyCredentialProvider(relyingPartyIdentifier:
  "sync.sstools.co")` (the platform provider, not the security-key provider).

## Expected outcome

After this lands plus the Mac-side entitlement: an account registered in the
browser can sign in from the Mac app by selecting the iCloud Keychain passkey,
with no second enrollment. AASA reachable at the URL above; discoverable
assertion issues a JWT access + refresh token pair.

## Verification

`curl -sS https://sync.sstools.co/.well-known/apple-app-site-association` returns
the expected JSON with the correct content type and no redirect; an end-to-end
test registers a credential via the web ceremony and authenticates it through
the discoverable-login path without supplying an email.
